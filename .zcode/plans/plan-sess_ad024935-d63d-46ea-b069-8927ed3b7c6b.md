# 4′ D3D11 渲染直通 落地计划

## 目标

现状通路（硬解之后仍有三段大块内存搬运，60fps ≈ 2.4GB/s 内存流量）：
```
GPU解码帧(NV12) --①下载8MB--> CPU --②sws转BGRA 16MB--> 内存 --③GDI读16MB--> DWM
```
目标通路（全程 GPU，垂直同步）：
```
GPU解码帧(NV12) → ID3D11VideoProcessor 转 BGRA → 交换链 Present(1)
```
收益：CPU 6%→约1-2%、无撕裂、少一次 present 延迟、解锁 `--fps 120`。

## 技术决策（已验证）

| 决策 | 选择 | 依据 |
|---|---|---|
| D3D 绑定 | Vortice.Direct3D11 **3.8.3**（NuGet 已确认） | 活跃维护的 C# 绑定，纯手写 COM 不现实 |
| 设备所有权 | C# 端创建 ID3D11Device，注入 ffmpeg `AVD3D11VADeviceContext` | 解码纹理必须属于渲染设备，免跨设备共享 |
| COM 生命周期 | 交给 ffmpeg 的四个接口带 AddRef（ffmpeg teardown 会 Release） | 已核对 n8.1 头文件语义 |
| NV12→RGB | ID3D11VideoProcessor（厂商视频处理单元） | 比 shader 省事，硬件加速 |
| 线程模型 | **渲染在解码线程执行**（Present 异步入队） | 避免 ImmediateContext 跨线程竞争；另开 SetMultithreadProtected 双保险 |
| 光标 | 30×36 精灵建 GPU 纹理，D2D 叠画在视频上（位置仍来自 60Hz 回报） | CPU 帧缓冲不复存在 |
| 回退 | **现有 CPU 管线（sws+GDI）完整保留**，GPU 任一步失败自动切回 | 绝不做"要么 GPU 要么崩" |

## 代码改动清单（Mac 端零改动，协议不变）

1. **csproj**：+ Vortice.Direct3D11 3.8.3（显式加 Vortice.DXGI、Vortice.Direct2D1、Vortice.Mathematics）
2. **新文件 `GpuVideoRenderer.cs`**（约 400 行）：
   - `Initialize(hwnd)`：D3D11CreateDevice（支持 BGRA）→ DXGI 工厂 → 交换链（FLIP_SEQUENTIAL, B8G8R8A8, 2 缓冲）→ D2D 设备/上下文 → 构造 ffmpeg 硬件设备引用（alloc → 填四个接口指针(AddRef) → init）→ 创建 VideoDevice/ProcessorEnum/Processor（枚举确认 NV12→BGRA8）
   - `HwDeviceRef` 属性：供 VideoDecoder 解码使用
   - `RenderFrame(AVFrame*, 光标参数)`：取 `data[0]` 纹理 + `data[1]` 切片号 → InputView；等比算 DestRect；设 ColorSpace（BT.709 limited→full，防发灰）；ClearRenderTargetView(黑) → VideoProcessorBlt → D2D 画光标 → Present(1)
   - `Resize(w,h)`：ResizeBuffers + 重建视图
   - `SetCursorSprite(bytes,w,h)`：BGRA → GPU 纹理 + D2D 位图
3. **`VideoDecoder.cs` 改造**：
   - 新属性 `ExternalHwDeviceRef`（Form 在 Start 前注入）；Open() 有外接设备时用 alloc+填充方式替代自建
   - ReadLoop：有 renderer 且帧为 D3D11 格式 → 解码线程直接 `renderer.RenderFrame(...)`，成功即 frameCount++/FrameReady；连续失败 → 置回退标志通知 Form
   - 软解兜底与 CPU 回退路径（下载+sws+BGRA）**原样保留**
4. **`ReceiverForm.cs` 改造**：
   - StartDecoder 前 try 创建 GpuVideoRenderer；成功 → 注入 ExternalHwDeviceRef + Renderer
   - GPU 模式下 PaintTick 跳过 CPU blit（保留状态栏/延迟统计）；Resize 事件转 renderer.Resize
   - 状态栏加渲染路径标识：`渲染 GPU` / `渲染 CPU`
   - 新增简易滚动日志文件 `%APPDATA%\MacScreenExtender\receiver.log`（远程迭代必需——Windows 端没有终端输出）
5. **诊断**：GPU 初始化每一步的成败都落日志；失败点精确到行

## 风险与对策

| 风险 | 对策 |
|---|---|
| Vortice API 细节偏差（盲写） | 交叉编译类型检查 + 运行期分步日志定位 |
| NV12 纹理数组切片 | `data[1]` 即切片索引；InputView 按帧创建（廉价） |
| 设备上下文多线程 | ffmpeg 内部互斥 + SetMultithreadProtected(TRUE) + 渲染单线程化 |
| 画面发灰 | VideoProcessorColorSpace 显式 709/limited→full |
| 驱动不支持 BGRA 输出视图 | 初始化时枚举检查，失败走 CPU 回退 |
| FLIP 模型与 WinForms | 标准 hwnd 交换链；备选 FLIP_DISCARD |
